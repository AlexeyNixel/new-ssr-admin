# Карточка «Последние изменения» на главной

**Дата:** 2026-09-22

## Задача

На бэкенде появился журнал изменений (`GET /audit-log` — кто, когда, какую сущность и как изменил). Нужно было вывести последние изменения на главный экран админки.

## Что сделано

- `services/types/audit-log.type.ts` — `AuditLogEntry`, `AuditLogQuery`.
- `services/api/audit-log.api.ts` — `useAuditLogApi().getAuditLog(params)`.
- `services/endpoints.ts` — добавлен `auditLog: '/api/audit-log/'`.
- `app/pages/index.vue` — четвёртая карточка «Последние изменения» в блоке «Активность» (сетка `lg:grid-cols-3` → `lg:grid-cols-2 xl:grid-cols-4`), по паттерну уже существующих трёх карточек. Последние 5 записей, бейдж действия (Создано/Изменено), человекочитаемое название типа сущности (словарь `ENTITY_LABELS` на все 19 типов бэкенда), время и автор.
- Ссылка на редактирование — только для 10 типов, где точно известен рабочий URL (проверено по `docs/deep-links.md` + текущему коду): Post, Department, Event, MainSliderSlide, Notification, MapPoint, Book, BookCollection, NavigationItem, Club. Для `Page` ссылку не делал — бэкенд ищет её по `slug`, а в журнале есть только `id` (проверил `page.service.ts` на бэкенде — реально упало бы в 404/500).

## Проверка

Прогнал вживую через `npx nuxi typecheck` (весь новый код — чисто, единственная ошибка в `index.vue` — на строке кода, которую не трогал, существовала до меня) и через реальный браузер (chrome-devtools MCP): завёл временного тестового пользователя через `POST /api/auth/register`, залогинился, увидел карточку с реальными записями, проверил консоль — ошибок нет. Тестового пользователя после проверки удалил.

## Найденный баг по пути (не мой, не чинил)

При **первой попытке** сделать ссылки через `<component :is="'NuxtLink'">` (строкой) — ссылки рендерились без роли `link`, клик не работал: `:is` с именем компонента строкой не резолвится через рантайм-реестр Nuxt. Исправлено на `import { NuxtLink } from '#components'` + `:is="condition ? NuxtLink : 'div'"` — так работает.

Отдельно, уже не связанное с моим кодом: **клик по ссылке `?editId=<id>` с главной страницы (SPA-переход) не подгружает сущность** — модалка открывается в режиме «Создание», а не «Редактирование». Проверил: то же самое происходит и на уже существующей карточке «Активные уведомления» (`NuxtLink`, код не мой) — то есть это существующая особенность `useModalRouteOpener`/`useModalEntity`, а не что-то, что я сломал. При прямом заходе по URL (или обновлении страницы) всё работает корректно. Моя карточка ведёт себя так же, как остальные три — специально не костылил только для неё, чтобы не расходиться с общим паттерном. Стоит завести отдельную задачу на разбор `useModalRouteOpener` (похоже, `route.query.editId` читается не реактивно при клиентской навигации между разными страницами SPA).
