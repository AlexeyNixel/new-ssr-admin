# Раздел «Игры» в админке

## Задача

Реализовать создание и редактирование игр в админ-панели — бэкенд
(`GET/POST/PATCH /games`, `/games/genres`, `/games/series`) уже готов и
отдаёт реальные данные (668 игр, 29 жанров, 64 серии).

## Что сделано

Собрано строго по существующим паттернам проекта (см. `CLAUDE.md`) —
ближайший аналог — книги (`Book`/`BookCollection`).

- `services/types/game.type.ts`, `services/api/game.api.ts` — типы и API-слой.
  `getAllGenres`/`getAllSeries` — через `getWithoutPagination` (эти два
  эндпоинта отдают массив без `{data, meta}`, в отличие от `getAllGames`).
- `services/endpoints.ts` — добавлены `game`, `gameGenre`, `gameSeries`.
- `app/schemas/game.schema.ts` — zod-схема (обязательны только `title`/`status`).
- `app/components/Ui/SelectGenre.vue`, `SelectSeries.vue` — по образцу
  `SelectTag.vue`: мультивыбор (жанры) / одиночный выбор (серия) с созданием
  «на лету» через `POST /games/genres`/`/games/series`.
- `app/components/Ui/UploadImages.vue` — **новый** компонент, которого раньше
  не было в проекте: до 3 изображений (переиспользует `useUploadApi().uploadImage`).
- `app/components/Ui/UploadDocument.vue` — точечно расширен: добавлены
  опциональные `modelValue`/`preview` + `emit('update:modelValue')` для
  привязки к полю формы (`rulesFileId`). Раньше компонент только показывал
  ссылку для копирования, v-model не поддерживал. Единственное текущее
  использование (`post/admin/[[slug]].vue`) не передаёт эти пропсы — не задето.
- `app/components/Modals/AdminGame.vue` — форма по образцу `AdminBook.vue`:
  картинки, название/статус, краткое/полное описание (`EditorCustom`),
  игроки/возраст/длительность/год, жанры, серия, ссылка на видео, PDF правил,
  место/комментарий, видимость (`isDeleted`).
- `app/pages/game/index.vue` — список (по образцу `book/index.vue`): обложка,
  название + бейдж серии, статус (в фонде/на руках/списана и т.д.) + бейдж
  видимости, дата, поиск, пагинация, deep-link `?editId=`.
- `app/components/LayoutAside.vue` — пункт меню «Игры».

Отдельные страницы управления жанрами/сериями сознательно не делал — создание
«на лету» из формы игры уже покрывает запрошенное («админка для создания и
редактирования игр»), отдельные справочники — по запросу отдельно.

## Проверка

- `npx tsc --noEmit -p .nuxt/tsconfig.json`, `npx eslint` по всем новым/
  изменённым файлам — чисто (в проекте есть 2 pre-existing ошибки в
  `EditorImageUploadExtension.ts`/`nuxt.config.ts`, не мои, не трогал).
- **Вживую в браузере** (chrome-devtools, `npm run dev`, реальный бэкенд на
  :3300): список игр — 646 активных записей, обложки, бейджи серий (AZUL и
  его дополнения показывают одну серию), статусы — без ошибок в консоли.
  Создание игры: заполнил название + жанр, отправил — запись появилась в
  списке (647), тост «Игра создана». Редактирование: открыл созданную игру —
  все поля (включая жанр) корректно подтянулись с сервера. Тестовые данные
  удалены после проверки.

## На заметку

- Обложки/файлы отдаются через `http://static.infomania.ru${path}` — тот же
  хардкод хоста, что уже используется для книг/сборников/клубов (см.
  «Известные особенности» в CLAUDE.md), не трогал.
- Хэндлеры `create()`/`update()` в `useApi()` не разворачивают `{data}` для
  `patch()` — но ни одна форма в проекте (включая новую) не читает
  возвращаемое значение `updateX()`/`createX()` напрямую, кроме
  `SelectGenre`/`SelectSeries`, где `createGenre`/`createSeries` идут через
  `api.post()` (без разворачивания) — это совпадает с тем, что реально
  отдаёт бэкенд (сырой объект без обёртки). Несовместимости нет.
